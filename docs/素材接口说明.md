# 素材接口说明

> 面向**美术/平面素材**这一侧。代码侧对应 `com.yestercar.common.util.AssetPaths`，
> 两边路径必须一致；改这份文档时同步改那个类，反之亦然。

---

## 一、最重要的规则

**贴图可以随时增量交付，缺了不影响程序运行。**

策划方案 §2.12 定的规则：程序启动时检测贴图文件是否存在——

| 情况 | 程序行为 |
| --- | --- |
| 贴图存在 | 画贴图 |
| 贴图不存在 | 画默认色块 |

所以**不需要等素材齐了才能开发**；反过来，素材丢进目录就能立刻看到效果，
不需要改任何代码。

---

## 二、文件放哪里

全部放在 **`src/main/resources/data/textures/`** 下：

```text
src/main/resources/data/
  enemies.json                 ← 代码读的敌人数据
  operators.json               ← 代码读的干员数据
  textures/
    terrain/                   ← 地形（5 种，最优先做这一组）
      impassable.png
      ground.png
      high.png
      red_door.png
      blue_door.png
    enemies/                   ← 敌人
      soldier.png
      archer.png
    operators/                 ← 干员
      guard_01.png
      sniper_01.png
```

> **为什么放 `resources` 而不是工程根的 `data/`**
> 工程根的 `data/` 是玩家运行时产出数据（地图、关卡 JSON），会被写。
> `resources/` 是只读素材，会被打进 jar，换机器也在。
> 这个区分是刻意的，见交接文档 §4.4。

## 三、命名规范（**硬性要求**）

文件名必须与数据文件里的 `id` **完全一致**，代码靠这个自动关联：

| 类型 | 文件名来源 | 示例 |
| --- | --- | --- |
| 地形 | 固定 5 个名字，见上表 | `ground.png` |
| 敌人 | `enemies.json` 中该敌人的 `id` + `.png` | `soldier.png` |
| 干员 | `operators.json` 中该干员的 `id` + `.png` | `guard_01.png` |

规则：

- **全小写**，单词之间用**下划线** `_`；
- 只用 `a-z`、`0-9`、`_`，**不要用中文、空格、大写字母、连字符**；
- 后缀一律 `.png`。

已经定好的 ID（与代码里的数据文件一致）：

```text
地形    impassable  ground  high  red_door  blue_door
敌人    soldier  archer
干员    guard_01  sniper_01
```

新增敌人/干员时，先在 `enemies.json` / `operators.json` 里定 `id`，再按那个 `id` 命名贴图。

## 四、尺寸规范

| 项 | 规格 |
| --- | --- |
| 格子基准尺寸 | **64 × 64 px**（与地图契约 `tileSize` 默认值一致） |
| 地形贴图 | **64 × 64 px**，必须铺满画布，不要留透明边 |
| 敌人贴图 | 建议 64 × 64 px，**内容居中、四周留 4~6 px 透明边**（避免和相邻格贴在一起） |
| 干员贴图 | 建议 64 × 64 px，同上；**需明确表示朝向**（默认按朝右画） |
| 格式 | PNG，**带透明通道**（RGBA） |
| 颜色模式 | sRGB |

**朝向的处理**：程序按部署/移动方向旋转贴图，所以**干员与敌人只需要画一张朝右的**，
不必画 4 个方向。

**红蓝门**：建议画成明显的门形，且两者颜色差异要大——它们在 12×8 的小地图上是关键视觉锚点。

**分辨率**：素材按 64 px 画即可，不要先画 256 px 再让程序缩——
Processing 的缩放会糊，而且程序默认 `pixelDensity = 1`（交接文档 §4.2）。

## 五、默认色块是什么样

贴图缺失时程序用色块代替。美术可以据此决定优先级——**色块的辨识度已经够用**，
所以贴图是「加分项」不是「阻塞项」：

| 地形 | 建议色块 | 说明 |
| --- | --- | --- |
| `empty`（-1） | 深灰 | 未放置，仅编辑器里出现 |
| `impassable`（0） | 近黑 | 不可通行 |
| `ground`（1） | 中灰 | 可通行地面，占地最大 |
| `high`（2） | 蓝灰 | 高台，只能放远程/医疗 |
| `red_door`（3） | 红 | 敌人出生点 |
| `blue_door`（4） | 蓝 | 防守目标，带血量显示 |

## 六、交付与检查

### 交付方式

直接放进 `src/main/resources/data/textures/` 对应子目录，文件名按第三节规则。

### 自查清单

- [ ] 文件名与 `id` 完全一致（区分大小写，全小写）
- [ ] 是 PNG 且带透明通道
- [ ] 地形图铺满 64×64，无透明边
- [ ] 干员/敌人是**朝右**画的
- [ ] 敌人与干员的红蓝方辨识度足够

### 确认程序读到了

跑一次环境自检，它会列出贴图的存在情况：

```powershell
tools\build.cmd
java -jar target\YesterCar.jar --check
```

也可以直接在游戏里看：**换成贴图后不需要改代码**，重新构建即可生效。
