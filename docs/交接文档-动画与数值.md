# 交接文档：骨骼动画 / 特效 / 数值

> 接收人任务范围：**干员与敌人的骨骼动画（Spine 等）、技能/攻击/治疗特效、双方数值设定**。
> 你手上有 AI 辅助，本文按"AI 能读懂、能照着改"的方式写。

---

## 一、先跑起来

```bash
# 需要 JDK 17 + Maven
mvn -B clean package
java -jar target/YesterCar.jar            # 游戏本体
java -jar target/YesterCar.jar --editor   # 战役编辑器
```

`dist/` 下有打好包的两个 exe（游戏 / 编辑器），双击即用，内置 JRE。

---

## 二、目录与路径规则（**不需要改任何路径**）

代码里**没有任何绝对路径**，全部走相对路径 + 运行时解析：

| 资源类型 | 位置 | 说明 |
| --- | --- | --- |
| 图片 / 音频 / 用户战役 | `data/` | 与 exe 或工程根**同级** |
| 只读数据（干员、敌人、官方关卡） | `src/main/resources/data/` | 打进 jar |

`Workspace.projectRoot()` 的解析顺序：

1. 系统属性 `yestercar.home`（显式覆盖）
2. 从 class 文件位置向上找含 `pom.xml` 的目录
3. `user.dir/data` 存在时用 `user.dir`
4. 兜底 `user.dir`

**换机器只需要保证 `data/` 跟着走**，代码不用动。用 exe 时 `data/` 和 exe 同级；用 jar 时 `data/` 在启动目录。

### 3.2 敌人 `src/main/resources/data/enemies.csv`

```csv
id,name,hp,atk,def,res,speed,attackInterval,blockWeight,ranged,rangeRadius,taunt,icon,damageType
caster_elite,高阶术师,500,130,20,40,0.9,2.2,1,1,3,0,data/imgs/enemy/高阶术师.png,arts
```

- `blockWeight = 0` → **不可被阻挡**（幽灵就是这么做的）

## 四、特效要挂在哪里（**已预留**）

战斗引擎每 tick 产出一串**事件**，特效播放器接在事件上即可，不需要改任何战斗逻辑。

事件类型见 `BattleDirector.BattleEvent.Kind`：

| Kind | 含义 | 可用字段 |
| --- | --- | --- |
| `ATTACK` | 某单位出手 | 攻击者 seq、目标 seq |
| `DAMAGE` | 造成伤害 | 数值 + `"phys"` / `"arts"` |
| `DIE` | 死亡 | 单位、坐标 |
| `EXTRA` | **扩展事件** | `"heal"`（治疗，数值=回血量）、`"slow"`（减速） |

**建议**：新建 `runtime/view/EffectLayer`，在 `BattleScreen.renderFrame()` 里取当前帧事件、生成粒子/贴图并更新。

> 现有代码里已经有 `puff[]`（击杀烟雾）的实现，可作为最简单的参考样例。

## 五、骨骼动画要接在哪里（**需要你新增实现**）

现状：干员/敌人是**色块 + 箭头 + 血条**占位（见 `BattleScreen.drawOperators()` 与 `drawEnemyUnits()`）。

**预留的接入点**：

1. **资源目录约定**（建议，按此放素材）
   ```
   data/spine/operator/<id>/   *.skel|*.json + *.atlas + *.png
   data/spine/enemy/<id>/
   ```

2. **渲染替换点**：把 `drawOperators()` 里写色块的 `g.rect/circle` 换成"按 state 选动画并绘制"。

3. **需要的单位状态**（`BattleDirector.UnitView` 已提供）：

   ```
   col,row,facing,name,hp,maxHp,blocking,block,atk,def,res,attackAge,hitFlash
   ```

   - `attackAge`：距上次出手的时间（秒）→ 驱动 攻击/治疗 动画
   - `hitFlash`：受击闪白计时
   - `blocking`：当前阻挡数 > 0 → 可播"战斗中"循环

4. **建议新增的类**（把动画逻辑与战斗逻辑隔离）：

   ```java
   interface UnitAnimator {
       void update(float dt, BattleDirector.UnitView view, int facing);
       void draw(processing.core.PApplet g);   // 世界坐标 → 屏幕由 Camera.project 负责
   }
   class SpineAnimator implements UnitAnimator { ... }
   ```

   在 `BattleScreen` 里持有 `Map<String, UnitAnimator>`，`drawOperators()` 逐个调用即可。

## 六、数值与规则（改数值前先看这节）

| 规则 | 值 |
| --- | --- |
| 模拟频率 | **固定 1/30 秒**（外部 dt 只进累加器，单帧最多 8 tick） |
| 物理伤害 | `max(atk - def, 0.05 * atk)` |
| 法术伤害 | `max(atk * (1 - res/100), 0.05 * atk)` |
| 治疗 | 射程内**血量比例最低**的友军，回血量 = 攻击力，不超上限 |
| 减速 | 命中后移速 ×0.5、持续 2 秒、重复命中只刷新时长 |
| 费用 | 每秒回费，**上限 99**；撤退返还 50%（向下取整） |
| 部署上限 | 同屏 8 人；编队最多 12 人 |
| 生命 | 全局共享一个池，默认 3，按关卡配置 |

## 七、容易踩的坑

1. **音频只支持 WAV/AIFF**。给 `.mp3` 会静默失败；用 ffmpeg 转单声道 22.05kHz。
2. **渲染器是 P2D（OpenGL）**，不是 JAVA2D。贴图旋转/贝塞尔等要确认 P2D 支持。
3. **窗口缩放会重建 `MainMenu`/`SquadScreen`**。跨重建要保留的状态必须显式迁移或设为 `static`（已踩过多次坑）。
4. 编辑器「测试」生成的战役目录 `_debug` 不会出现在玩家列表，别删。
5. 改完跑一次 **`mvn -B clean package`**：现有 **380 个测试**，红一个都说明破坏了既有行为。
6. 别直接改 `dist/` 里的 jar；改源码后重新打包。
