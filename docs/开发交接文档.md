## 三、⚠️ 环境配置中的陷阱

按「踩到就浪费半天」的程度排序。前三条是必须知道的。

### 1. `JAVA_HOME` 默认指向 JDK 11，**不能用**

```
JAVA_HOME = D:\A\jdk-11.0.25      ← 系统默认，Processing 4 不支持
```

Processing 4 要求 **Java 17**。三条应对措施都已就位：

- `pom.xml` 里写 `<maven.compiler.release>17</maven.compiler.release>`；
- `tools\build.cmd` 与 `tools\install-g4p.cmd` 会自动把 `JAVA_HOME` 切到 JDK 17；
- IDEA 里项目 SDK 已设为 17（`.idea/misc.xml` 中 `project-jdk-name="17"`）。

命令行手工跑 Maven 时要临时指定：

```powershell
$env:JAVA_HOME="C:\Program Files\Java\jdk-17"
mvn clean test
```

> 补充事实：PATH 上的 `java` 其实是 17.0.12，只有 `JAVA_HOME` 指向 11。
> 所以 `java -version` 看着没问题，但 Maven 用的是 `JAVA_HOME`，仍然会失败。

### 2. `.mvn/maven.config` 用**平台字符集**解码，写中文会让 Maven 直接崩

Maven 读取 `.mvn/maven.config` 时用的不是 UTF-8，而是平台默认字符集。在中文 Windows（GBK）上：

```
java.io.UncheckedIOException: java.nio.charset.MalformedInputException: Input length = 1
    at org.apache.maven.cli.MavenCli.cli(MavenCli.java:386)
```

Maven **直接启动失败，连 `pom.xml` 都没读到**，而且报错完全不提示是哪个文件的问题。

**规定：`.mvn/maven.config`、`tools/*.cmd` 一律保持纯 ASCII，中文注释只写在 `.md` 与 `.java` 里。**

Java 源码本身不受影响（`pom.xml` 已声明 UTF-8，`maven.config` 里也补了 `-Dfile.encoding=UTF-8`）。

### 3. G4P 不在任何 Maven 仓库上，且**阿里云镜像会劫持 file:// 仓库**

G4P 只通过 SourceForge 分发，本机网络不可达；阿里云 public 仓库里也没有 `org.g4p`。

原本按「项目内 `file://` 仓库」引入，但实测**行不通**——本机 `~/.m2/settings.xml` 里有：

```xml
<mirror>
  <id>aliyunmaven</id>
  <mirrorOf>*</mirrorOf>          ← 通配符把 file:// 仓库也一起劫持了
  <url>https://maven.aliyun.com/repository/public</url>
</mirror>
```

结果 Maven 绕过项目内仓库，去阿里云找 `org.g4p:g4p`，报：

```
Could not find artifact org.g4p:g4p:jar:4.3.11 in aliyunmaven
```

**现行方案：把 G4P 装成「本地仓库」布局，而不是「远程 file:// 仓库」。**
Maven 对已存在于本地仓库的构件不会发起远程请求，镜像配置完全无法干扰。

```text
.mvn/repo/                                    ← 本地仓库布局 = ~/.m2/repository 的布局
  org/g4p/g4p/4.3.11/g4p-4.3.11.jar
  org/g4p/g4p/4.3.11/g4p-4.3.11.pom
```

路径由 `.mvn/maven.config` 的 `-Dmaven.repo.local=.mvn/repo` 固定；G4P 由 `tools/install-g4p.cmd` 装入。

`pom.xml` 里因此**不需要** `<repositories>` 声明，G4P 就是一条普通依赖：

```xml
<dependency>
  <groupId>org.g4p</groupId>
  <artifactId>g4p</artifactId>
  <version>4.3.11</version>
</dependency>
```

**新队友上手只有两条命令**：

```powershell
tools\install-g4p.cmd     # 装 G4P 进项目内本地仓库（只需一次）
tools\build.cmd           # 构建 + 跑测试
```

> 另有两条容易忽略的规则：
> - **`.gitignore` 里绝对不能写 `*.jar`** —— `third_party/G4P/library/G4P.jar` 是全项目唯一的 G4P 来源；
> - `.mvn/repo/` 已在 `.gitignore` 中忽略（上百 MB，可重建），但 `third_party/G4P/` 必须入库。

### 4. PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写 BOM

BOM 会让编译器报：

```
Syntax error on token "Invalid Character", delete this token
```

**所有源文件一律用 IDEA / VS Code 保存为 UTF-8 无 BOM。**
必须用命令行生成时用：

```powershell
[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))
```

本项目现有源码已全部核验为 UTF-8 无 BOM。

### 5. 控制台显示的「中文乱码」多半是假象

PowerShell 控制台用 GBK 解释 JVM 输出的 UTF-8 字节，于是 `=== YesterCar 启动 ===`
显示成 `=== YesterCar 鍚姩 ===`。**文件本身是好的**，用 IDEA 打开即正常。

不要在没核实的情况下把文件「转成 GBK」——那才会真把文件弄坏。

### 4.2 `pixelDensity()` **只能在 `settings()` 里调用**

这是本项目踩到的最贵的一个坑，表现为「窗口打不开」，但报错信息指向别处。

在 Maven 工程（非 PDE）下，把 `pixelDensity(1)` 放在 `setup()` 里：

```
When not using the PDE, pixelDensity() can only be used inside settings().
java.lang.IllegalStateException: pixelDensity() cannot be used here
    at processing.core.PApplet.insideSettings(PApplet.java:837)
    at com.yestercar.common.util.UITheme.apply(UITheme.java:93)
    at com.yestercar.splash.SplashScreen.setup(SplashScreen.java:35)
    at processing.core.PApplet.handleDraw(PApplet.java:2055)
    at processing.core.PSurfaceNone$AnimationThread.run(PSurfaceNone.java:356)
```

后果**不是**「密度没设成」，而是**整个渲染循环被异常打断**：窗口对象已经创建、
在 `EnumWindows` 里能看到，但既不绘制也不响应，从外面看就是「主窗口没打开」。

**正确写法**（`UITheme.disablePixelDensityScaling` 必须在 `settings()` 内调）：

```java
@Override
public void settings() {
    size(WINDOW_W, WINDOW_H, JAVA2D);
    UITheme.disablePixelDensityScaling(this);   // 只能在这里
}

@Override
public void setup() {
    UITheme.apply(this);                        // 配色 + 中文字体
    // ... 创建 G4P 控件
}
```

### 4.3 `user.dir` 不可靠，**不能**当作「工程根」

实测：从资源管理器或后台方式启动 `java -jar` 时，`user.dir` 会退化成
`C:\Users\ASUS\Documents`，于是 `data/maps` 会被建到「文档」目录里。

`Workspace.projectRoot()` 因此按优先级解析（已实测第 1、2 条生效）：

| 优先级 | 依据 | 结果 |
| --- | --- | --- |
| 1 | 系统属性 `-Dyestercar.home=...` | 显式指定，最高优先级 |
| 2 | 从 class 文件位置向上找含 `pom.xml` 的目录 | ✅ IDEA 运行与 `java -jar` 都正确解析到工程根 |
| 3 | `user.dir/data` 已存在 | 次选 |
| 4 | `user.dir` | 兜底 |

两类数据路径（见 §4.4）都建立在 `projectRoot()` 之上。

### 4.4 路径行为：两类数据

```
sketchPath() = <user.dir>          ← 不可靠，见 §4.3
dataPath()   = <user.dir>/data     ← 因此也不能依赖
```

方案采用两类路径：

| 类别 | 位置 | 读取方式 |
| --- | --- | --- |
| 只读默认数据 | `src/main/resources/data/` | classpath `getResourceAsStream` |
| 用户产出数据 | `<工程根>/data/`，由 `Workspace` 显式解析 | 文件系统读写 |

### 4.6 中文字体

本机实测可用的中文字体族：`Microsoft YaHei`、`Microsoft YaHei UI`、`SimHei`、
`SimSun`、`DengXian`、`KaiTi`、`FangSong`、`Microsoft JhengHei`（共 296 个字体族）。

项目统一用 `Microsoft YaHei`。**G4P 找不到指定字体会静默回退到 Arial，中文就变方块**，
所以换字体前先确认该字体确实存在。

### 4.7 Processing JSON 对负数 key 的行为

地图契约里 `legend` 用 `"-1"` 当 key。Processing 的 `JSONObject` 内部以 **String** 存 key，
因此必须用 `getString("-1")` 读取；用 `getInt("-1")` 会抛 `RuntimeException`。
`Stage1SmokeTest` 里已把这条行为锁成断言，Processing 升级后若行为变化会立刻失败。

## 六、历史包袱：Processing sketch 路线的结论

已放弃该路线，代码已删除，但结论保留（若将来需要写 Processing sketch）：

| 结论 | 说明 |
| --- | --- |
| sketch **不支持 `package`** | 子目录中的 `.java` 被静默忽略；`import xxx.Yyy` 报 `No library found for xxx` |
| `.pde` 文件里的类是**内部类** | 编译产物 `SketchName$ClassName.class` |
| sketch 根目录的 `.java` 是**顶层类** | 编译产物 `ClassName.class` |
| PDE 把 `.java` 也当标签页 | `Sketch.load()` 用 `mode.getExtensions()`（pde + java）扫描根目录 |
| `PApplet.runSketch()` 可用 | 多窗口可行，已在 Maven 环境下重新确认（见 §6.1） |
| 无头构建 | `Processing.exe cli --sketch=... --build/--run/--export` |

**弃用理由**：无法分包，大型项目只能所有类平铺一层；无法做单元测试；构建模型怪限制多（BOM、tab、路径）。

### 6.1 窗口机制结论（原第一阶段规划 §九 的待办）

两个方案都实测过：

| 方案 | 机制 | 结论 |
| --- | --- | --- |
| **A** | `PApplet.runSketch(String[], PApplet)`，每个模块是独立 `PApplet` 子类 | ✅ **采用**。实测启动窗 → 主窗口切换正常，主窗口能挂 G4P 控件 |
| B | G4P `GWindow.getWindow()` + 绘制回调 | 备选。G4P 官方多窗口示例走这条路 |

**选 A 的理由**：与策划方案 §10.1.4「各模块窗口类继承 `PApplet`」一致，类结构更自然。
`GWindow` 留作「同一个 PApplet 内开附属面板」时使用。

> 关窗行为：主窗口建议拦截 ESC（`keyPressed` 里 `key = 0`），
> 因为 Processing 默认用 ESC 直接退进程，容易误关整个程序。
